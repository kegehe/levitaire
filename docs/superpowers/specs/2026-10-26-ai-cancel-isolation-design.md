# AI 请求取消隔离

## 问题与目标

工具栏在新选区、隐藏、返回默认态时重置 AI Hook。空闲取消向后端传递空请求 ID，后端会取消全部活动流。工具栏和 OCR 结果窗口还有独立递增但可能相同的请求 ID，且流式事件目前广播给所有窗口。

修复后，空闲取消仅清理本地状态；取消和卸载只终止自身已发出的请求；不同窗口、同一窗口重新挂载的组件，其同号请求、取消标记及结果事件彼此隔离。

## 设计

- 前端保留本地递增 ID 判断过期回调，只有实际发起后端调用时才记录活动请求 ID。取消和卸载仅在活动 ID 存在时调用后端。
- 每个 Hook 实例创建独立的 UUID `requestScope`，随调用、取消和结果事件传递。前端严格匹配实例标识和数字 ID，避免重新挂载或页面重载后的计数器重置造成串扰。
- 将监听注册纳入错误处理。注册期间取消或卸载，释放迟到的监听器且不发送请求；终止事件之后迟到的 IPC 错误不能覆盖已完成状态；IPC 异常与终止事件一样立即刷新最后一批文本并清理刷新定时器。
- 后端取消状态以 `StreamRequestKey { window_label, request_scope, request_id }` 为键。窗口身份从 Tauri 注入的调用窗口取得，不由前端传入。
- 空 ID 取消为无操作，保留可选参数以兼容现有调用协议；保留有界的提前取消记录以处理 IPC 先后顺序。
- 每个活动请求持有独立的 `CancellationToken`。在整个异步 HTTP 调用外使用 `tokio::select!`，优先响应取消并丢弃网络 future，覆盖响应头等待、错误正文读取和流式正文读取；取消不依赖服务端发送下一帧。沿用既有 `tokio-util` 依赖。
- 所有 AI 流事件定向发送给来源 WebviewWindow；前端监听也显式指定同一窗口目标，避免 Tauri 通用监听器仍然接收其他窗口的定向事件。事件负载保留原有数字请求 ID 并附带实例标识，无需改动业务界面。后端实例参数可选，以便旧调用仍能使用独立的无实例命名空间。

## 验证

- Hook：空闲、重复、完成后、失败后取消及卸载不发送无效取消；执行中准确取消一次；监听注册失败恢复状态；注册期间取消/卸载不启动请求；旧事件和延迟 IPC 错误不会覆盖结果；重新挂载拒绝旧实例事件；缺少 ID/实例标识的事件被忽略；取消、卸载、完成和 IPC 异常均清理批量刷新定时器。
- 工具栏：新选区、空闲 Esc、子菜单返回不发送取消；工具栏操作期间其他 Hook 的活动请求可以继续接收结果。
- Rust：空 ID 不取消；不同窗口同 ID 各自注册和取消；同一窗口不同实例同 ID 各自注册和取消；提前或迟到取消只作用于来源实例；释放一个请求不影响其他请求。
- 通过 `127.0.0.1` 临时 HTTP 服务验证响应头停顿、首段 SSE 文本之后停顿、错误正文停顿三个场景的主动取消；不访问第三方 AI 服务。
- 执行相关 Vitest、TypeScript 检查、Rust AI 测试及必要的格式检查。
