## 二、各产品详细分析

### 2.1 eSearch — 最接近的全功能竞品

| 维度 | 详情 |
|------|------|
| **产品定位** | 开源截图+OCR+录屏+悬浮工具栏一体化桌面工具 |
| **功能亮点** | ① 截屏、OCR、录屏、画板、搜索、翻译六合一 ② 截图后自动弹出悬浮编辑工具栏（标注/OCR/复制/保存/搜索）③ 离线 OCR 引擎集成 ④ 录屏支持导出 GIF/WebM ⑤ 支持以图搜图、二维码识别 |
| **技术栈** | Electron + TypeScript + React + Tesseract |
| **交互方式** | 全局快捷键唤起截图 → 框选区域 → 悬浮工具栏弹出 → 一键 OCR/翻译/搜索/编辑 |
| **与我们的差异** | 我们有但 eSearch 没有：① TTS 朗读 ② 系统监控 ③ 语音输入(STT) ④ AI 文本优化 ⑤ 桌面自动化(键盘鼠标钩子) ⑥ MD5/Unicode/去重/编号等文本处理工具链 |
| | eSearch 有但我们没有：① 录屏(GIF/WebM) ② 画板标注编辑 ③ 以图搜图 ④ 离线 OCR 引擎（我们用云端） |

### 2.2 Pot — 同技术栈（Tauri+Rust）翻译工具

| 维度 | 详情 |
|------|------|
| **产品定位** | 跨平台翻译工具，强调"划词翻译"+"截图翻译"+"悬浮窗" |
| **功能亮点** | ① 多翻译源聚合（OpenAI/DeepL/Google/百度等 20+）② 划词翻译（选中即译）③ 截图 OCR 翻译 ④ 剪贴板监听自动翻译 ⑤ TTS 朗读 ⑥ 悬浮窗模式 ⑦ 插件系统 ⑧ 离线 OCR 支持 |
| **技术栈** | **Tauri v2 + Rust + React + TypeScript**（与 floast 完全一致） |
| **交互方式** | 系统托盘常驻 → 选中文字自动弹窗翻译 → 截图翻译快捷键 → 悬浮窗始终可见 |
| **与我们的差异** | 我们有但 Pot 没有：① AI 文本优化/重写 ② 系统监控 ③ 桌面自动化 ④ 文字工具栏全功能（MD5/去重/编号/二维码等）⑤ 语音输入(STT) |
| | Pot 有但我们没有：① 多翻译源聚合 ② 划词自动翻译 ③ 插件系统 ④ 离线 OCR ⑤ 剪贴板监听自动翻译 |

### 2.3 screenpipe — 屏幕 AI 记忆方向

| 维度 | 详情 |
|------|------|
| **产品定位** | 开源 Rewind 替代，24/7 屏幕+音频录制 + AI 知识索引 |
| **功能亮点** | ① 24/7 屏幕连续录制（H.265 压缩，100x 压缩比）② 实时 OCR 提取屏幕文字 ③ 音频转录 ④ 向量嵌入构建可搜索记忆库 ⑤ 本地 LLM 集成（Ollama）⑥ 时间线回溯 ⑦ 隐私优先（本地处理） |
| **技术栈** | **Rust**（核心录制引擎）+ Swift/TypeScript + OCR + Embedding |
| **交互方式** | 后台静默运行 → 本地 API 查询 → "我昨天看到的那段代码是什么？"→ 返回截图/文字/时间 |
| **与我们的差异** | 完全不同的产品方向，但 screenpipe 的**连续屏幕录制 + OCR + AI 索引**是一个值得参考的技术方向。我们的截图是手动按需触发，screenpipe 是全自动连续。 |

| **划词自动翻译** | Pot, 有道词典 | ⭐⭐⭐ 高 |

| **贴图钉住**（截图钉在桌面） | Snipaste | ⭐⭐⭐ 高 |
| **剪贴板历史 + 搜索** | CopyQ, Ditto, EcoPaste | ⭐⭐ 中 |
| **插件市场/插件系统** | uTools, Rubick, Raycast | ⭐⭐ 中 |

| **24/7 屏幕录制 + AI 索引** | screenpipe, Rewind | ⭐ 低（大工程） |
| **自然语言控制桌面** | Open Interpreter | ⭐ 低（风险高） |
| **文件搜索**（Everything 级） | Listary, Flow Launcher | ⭐ 低 |

### 3.4 功能优势清单（我们有但竞品没有/少有的）

| 功能 | 说明 |
|------|------|
| **悬浮球 + 工具栏一体化** | 悬浮球常驻 → 选中文字弹出工具栏，交互模式独特 |
| **TTS 朗读** | 大多数竞品不做 TTS（Pot 除外） |
| **系统监控**（CPU/内存/网络/磁盘/电池） | 独立方向，竞品极少覆盖 |
| **AI 文本优化/重写** | 选中文字后 AI 优化润色，Raycast 有但需付费 |
| **丰富的文本处理工具链** | MD5/Unicode/Base64/去重/编号/二维码/清空/字符统计，一站式 |
| **桌面键盘鼠标钩子** | AutoHotkey 级别的事件监听能力 |
| **语音输入(STT) + 语音输出(TTS)** | 两者兼备的竞品极少 |
| **工具注册表架构**（懒加载/按需激活） | 插件式架构设计，扩展方便 |

## 四、技术架构对比（Top 3 最接近竞品）

### 4.1 Pot (pot-app/pot-desktop) — 同技术栈

```
┌─────────────────────────────────────────────────────┐
│                    Pot 架构                           │
├─────────────────────────────────────────────────────┤
│  前端: React + TypeScript                            │
│  桌面壳: Tauri v2 (Rust)                             │
│  后端: Rust (tauri 插件 + 独立逻辑)                   │
│  翻译: 多源 API 聚合层                                │
│  OCR: 离线 (PaddleOCR/Tesseract) + 在线 API           │
│  TTS: 系统 TTS / 在线 API                             │
│  插件: JavaScript 插件系统                            │
│  存储: 本地 JSON/SQLite                               │
└─────────────────────────────────────────────────────┘
```

**与 floast 对比**：
- ✅ 相同：Tauri + Rust + React + TypeScript
- ✅ 相同：TTS、翻译、OCR 功能方向
- ❌ Pot 多了一层插件系统，floast 是内置工具注册表
- ❌ Pot 的 OCR 支持离线引擎，floast 仅云端
- ❌ Pot 翻译聚合 20+ 源，floast 翻译较单一

### 4.2 screenpipe — Rust 高性能屏幕处理

```
┌─────────────────────────────────────────────────────┐
│                 screenpipe 架构                       │
├─────────────────────────────────────────────────────┤
│  录制引擎: Rust (H.265 硬件编码, 100x 压缩)           │
│  OCR: 本地 OCR 引擎 (Apple Native / Tesseract)       │
│  音频: 本地 Whisper 转录                              │
│  索引: 向量嵌入 + 全文搜索                            │
│  API: 本地 HTTP API (供 LLM 查询)                     │
│  存储: 本地 SQLite + 文件系统                         │
│  前端: TypeScript (管理界面)                          │
└─────────────────────────────────────────────────────┘
```

**与 floast 对比**：
- ✅ 相同：Rust 核心性能敏感模块
- ✅ 相同：OCR 文字提取
- ❌ screenpipe 是持续录制+索引模式，floast 是按需触发
- ❌ screenpipe 有向量嵌入 + AI 记忆搜索
- ❌ screenpipe 无悬浮工具栏交互

### 4.3 eSearch — 功能重叠度最高

```
┌─────────────────────────────────────────────────────┐
│                  eSearch 架构                         │
├─────────────────────────────────────────────────────┤
│  桌面壳: Electron                                     │
│  前端: React + TypeScript                             │
│  截图: Electron DesktopCapturer + 自绘选区            │
│  OCR: Tesseract.js / 在线 API                         │
│  录屏: MediaRecorder API → GIF/WebM                   │
│  画板: Canvas 自绘标注                                │
│  翻译: 在线 API                                       │
│  搜索: 以图搜图 / 文字搜索                             │
│  悬浮工具栏: 截图完成后弹出 React 组件                  │
└─────────────────────────────────────────────────────┘
```

**与 floast 对比**：
- ✅ 相同：截图 + OCR + 翻译 + 悬浮工具栏组合
- ✅ 相同：React 前端
- ❌ eSearch 用 Electron，floast 用 Tauri（更轻量）
- ❌ eSearch 有录屏、画板标注、以图搜图
- ❌ floast 有 TTS、系统监控、语音输入、桌面自动化、文本工具链
- ❌ floast 交互模式是悬浮球常驻 → 选中文字弹工具栏；eSearch 是截图 → 弹工具栏

## 五、总结与建议

### 核心发现

1. **没有完全一致的竞品**：floast 的"悬浮球常驻 + 多工具集成（文字处理 + 截图 OCR + AI + 语音 + 系统监控）"组合在市场上是独特的。

2. **最接近的竞品是 eSearch 和 Pot**，前者功能重叠度最高，后者技术栈完全一致。

3. **三个值得优先补齐的功能**：
   - **离线 OCR**（Pot/screenpipe 方案）
   - **截图标注编辑**（箭头/高亮/模糊，Snipaste 方案）
   - **多翻译源聚合**（Pot 方案）

4. **技术栈优势明显**：Tauri + Rust 比 Electron 更轻量（安装包 ~5MB vs ~80MB），是差异化竞争力。

5. **独特卖点**：TTS + STT 双语音 + 系统监控 + AI 文本优化 + 悬浮球交互，竞品均未同时覆盖。
