# 文件暂存架实现方案

> 目标：在 Levitaire 中新增一个悬浮工具「文件暂存架」。用户把手头的文件先放在一块常驻浮窗里，再拖进另一个窗口。它不整理磁盘，也不保存笔记。
>
> 本文档是实施规格。行为、数据和不变量以本文为准；与便利贴、钉图、剪贴板历史的边界以本文第二节为准。

---

## 一、结论摘要

1. **暂存架是一个独立悬浮工具**，注册进 `FLOATING_TOOLS`，类别为 `system`，默认关闭。它和便利贴一样是「放在桌面上的东西」，不是截图那种一次性模式，所以不放进通用工具的页签里。
2. **列表里记的是引用，不是副本。** 从资源管理器、桌面拖进来的文件和文件夹，只保存规范化后的路径。体积不因此翻倍，拖出去的仍是原来那个文件。
3. **易失路径上的文件必须在系统 Drop 返回前复制进暂存目录。** 浏览器拖出的文件常在 `%TEMP%`，Outlook 附件常在 `INetCache`，松手后源文件就被删掉。只记路径的话，条目会立刻失效。复制有单文件和总容量上限，超限就拒绝，不改记成一条会失效的引用。易失路径上的文件夹直接拒绝，不复制也不当引用。
4. **拖出去只允许复制，不允许移动。** 资源管理器拿到 `CF_HDROP` 里的路径后，若效果是 `MOVE`，会自己把原文件搬走。允许的效果写在 `DoDragDrop` 的 `dwOKEffects` 里，只传 `DROPEFFECT_COPY`，并在数据对象里放 `CFSTR_PREFERREDDROPEFFECT = COPY`。`IDropSource` 不负责返回拖放效果。不引入会同时广告 `MOVE` 的拖放库。
5. **前端不持有可删除的路径。** 移除、清空、拖出都传条目 `id`。真正落在暂存目录里的副本，删除前必须证明规范化路径仍在 `shelf/files` 之内，且沿途没有重解析点。引用条目的移除只改清单，不碰原文件。
6. **第一版只收文件和文件夹。** 纯文本、网址、emoji 仍走快速输入和便利贴。暂存架不变成第二个剪贴板。

## 二、和现有工具的边界

| 现有能力 | 它留下什么 | 暂存架补的缺口 |
|---|---|---|
| 便利贴 | 一段写下来的文字，图片贴进去是为了看 | 若干个还要拖进别的程序的文件 |
| 钉图 | 一张钉在最前的图，当参照 | 把这张图变成可以拖进聊天或上传框的文件 |
| 剪贴板 / 快速输入历史 | 复制然后粘贴，一次一条 | 同时捏着好几样，用拖拽交给目标窗口 |
| 系统清理 | 删除可证明安全的缓存 | 无关。暂存目录不进清理规则 |

## 三、不变量

代码评审和测试守卫以这张表为准。

| 编号 | 不变量 | 违反后果 |
|---|---|---|
| **S1** | `DoDragDrop` 的 `dwOKEffects` 只有 `DROPEFFECT_COPY`，数据对象里的 `CFSTR_PREFERREDDROPEFFECT` 也只有 `COPY`。`IDropSource` 只决定继续、取消或放下，不返回效果 | 同卷拖放或按住 Shift 时，资源管理器按移动处理，原文件离开原目录 |
| **S2** | 移除引用条目只改 `shelf.json`。删除磁盘文件的唯一入口是「这个条目的 `kind == owned`」 | 用户清掉一条引用，原文件被删 |
| **S3** | 删除 owned 文件前，路径必须规范化，且结果仍落在 `shelf/files` 根下；根自身或任一祖先是 junction / symlink / mount point 时整次操作失败 | 暂存目录被重定向后，删除打到别的盘 |
| **S4** | 前端命令只传条目 `id` 或「这次拖放事件给出的源路径」。不接受前端指定的目标路径，不接受前端指定的删除路径 | WebView 被篡改时可以指定任意路径去删 |
| **S5** | 易失路径上的文件只允许复制进暂存目录。复制失败或超限则拒绝这一项，不退回成引用。易失路径 = `GetTempPath`、路径中含 `\INetCache\`、`\Content.Outlook\` 或 `\Temporary Internet Files\` | 松手后源文件消失，列表里留下死链。只认临时目录会漏掉 Outlook 的附件缓存 |
| **S6** | 暂存架不复制、不展开文件夹。稳定路径上的文件夹记为引用。易失路径上的文件夹直接拒绝 | 复制整个盘符会撑满暂存目录；易失文件夹只记路径则会在松手后整夹失效 |
| **S7** | 同一时刻只有一个拖出会话。第二次 `shelf_begin_drag` 在第一次返回前直接失败 | 两个 `DoDragDrop` 叠在主线程上，窗口假死或效果错乱 |
| **S8** | 清单写入沿用 `config` 的原子写：临时文件 + `rename` 替换。加入失败时内存与磁盘都回到写前。删除副本时先删文件再写清单，清单写失败不回滚文件（见第十节） | 写到一半崩溃，下次启动清单损坏；删除路径若按「一律回滚内存」处理，会把已经删掉的副本显示成还在 |
| **S9** | 关闭浮窗、禁用工具、退出应用都不清空清单，也不删除 owned 文件 | 用户以为只是收起，重启后文件没了 |
| **S10** | 条目上限 30。第 31 项拒绝并提示，不自动丢掉最旧的一条 | 用户还要的那个文件被静默挤掉 |

## 四、第一版范围

### 做

- 一块置顶浮窗：列表、拖入、聚焦时粘贴、拖出、双击打开、移除、在资源管理器中显示、清空、收成一条。
- 工具面板卡片、启停、自启动、窗口位置记忆。
- 截图工具栏、长截图预览、钉图右键菜单增加「放入暂存架」，把当前 PNG 写成 owned 文件。
- 截图、录屏、长截图抓画面之前藏起暂存架，会话结束且工具仍启用再恢复。抓完缓存不要跟着时钟一起显示。时序见第十一节。

### 不做

- 文本、链接、富文本片段。
- 从暂存架拖出时移动或剪切原文件。
- 给文件夹做展开、预览、重命名、标签。
- 系统文件图标（`SHGetFileInfo`）。第一版按扩展名画通用图标：文件夹、图片、其它文件。
- 全局热键。打开方式是悬浮球面板和「启动时自动打开」。窗口聚焦后用 `Ctrl+V` 收入剪贴板里的文件或图片。
- 云同步、加密、版本历史。
- 把暂存目录注册进系统清理。用户数据，清理规则不得覆盖。

## 五、用户可见行为

窗口 label 为 `file-shelf-overlay`，标题以 `Levitaire` 开头（`is_own_window` 的标题前缀兜底靠这个）。无边框、置顶、不进任务栏，四周留白与通用工具相同（`panelWindow.ts` 的投影边距）。位置写入现有的 `window_positions["file-shelf-overlay"]`。

### 5.1 放进来

三条入口，进清单后的形态一致：

1. **拖入窗口。** 在系统 `IDropTarget::Drop` 返回之前由 Rust 收路径并完成易失文件的复制。前端的 `tauri://drag-drop` 只用来刷新清单，不再负责把路径交回去加入。Windows 上 WebView2 收不到 HTML5 drop，页面里的 `onDrop` 不能当主路径。Tauri 的拖放事件是 Drop 返回之后才派发的，只靠它会赶不上浏览器删临时文件。
2. **窗口聚焦时 `Ctrl+V`。** 剪贴板有 `CF_HDROP` 时按拖入同一套规则处理。只有位图、没有文件时，把图写成 PNG，成为 owned 条目。剪贴板两者都没有时，提示「剪贴板里没有文件或图片」，不把纯文本塞进来。
3. **截图 / 钉图的「放入暂存架」。** 后端收到 PNG 字节，写入暂存目录。工具未启用时不显示这个动作。

同一规范化路径已在清单里：不新增，把该条移到顶部，并在窗口里闪一下这一行。owned 的截图每次都是新文件，允许同时存在多张。

### 5.2 看着

- 默认宽 300 逻辑像素，高度随条目增长，超过 420 后列表内部滚动。空列表显示「把文件拖到这里」。
- 每行：类型图标、文件名、副文案。文件副文案是大小；文件夹是「文件夹」；失效条目是「找不到了」，整行变淡。
- 悬停文件名时 tooltip 补完整名称、大小和加入时间。单击选中，`Ctrl` 切换选中，`Shift` 从锚点按当前显示顺序连选，点面板空白处取消选择。
- 新条目在最上面。
- 按住磁贴拖动可以在架内调整顺序，同步显示其它格子让位，松手时顺序写回 `shelf.json`。两条以上才进入排序；按在磁贴上移动超过 6px 时，光标还在面板内就进入排序，一开始就在面板外或排序途中移出面板（含 14px 余量）才转为拖出。拖到列表上下边缘会自动滚动，`Esc` 取消排序并恢复原顺序。
- 标题栏可拖动整窗，用显式 `startDragging()`，不要 `data-tauri-drag-region` 的双击最大化。按钮、列表滚动条不触发拖窗。
- 收起后窗口变成一条高 36 的横条，只留图标和数量。再点一次展开。拖到收起态上的文件照常收入，并展开。收起状态写在 `shelf.json` 的 `collapsed` 字段里。
- 关闭按钮只隐藏窗口。工具开关仍是开启。下次从面板点开，清单还在。

### 5.3 拿出去

- 在一行上按下并移动超过 6px：光标还在面板里就进入架内排序；一开始就在面板外，或排序途中移出面板，才开始拖出这一条。
- `Ctrl` / `Shift` 点选可多选，拖其中任意一条时把当前选中的、且仍存在的条目一起拖出。失效条目不参与。一次最多 20 条；超出时拖出失败并提示，而不是静默截断。
- 双击条目用系统默认程序打开；文件夹交给资源管理器打开。失效条目没有这个动作。
- 松手在暂存架自己的窗口上：取消，清单不变。
- 「打开位置」调用资源管理器并选中该文件。文件夹则打开该文件夹。失效条目没有这个动作。
- 移除引用：行消失，原文件还在。
- 移除 owned：行消失，只删除暂存目录里的那一个文件。
- 清空：先确认「清单会清空。其中 N 个副本从暂存目录删除，引用的原文件留在原地」。N 为 0 时仍要说清单会清空，避免用户以为只删副本、引用还在。确认后逐条按上面的规则处理。

### 5.4 启停

与通用工具同一契约（`set_utility_hub_enabled`）：

- `file_shelf_enabled` 默认 `false`。旧 `config.json` 没有该字段时反序列化为 `false`，不要把新工具突然铺到所有用户桌面上。
- 面板点卡片：先启用，再显示窗口。
- 禁用：隐藏窗口。不删 `shelf.json`，不删 `shelf/files`。
- 「启动时自动打开」走现有 `tools_autostart`。`FloatingOrb` 已按 `openToolWindow` 分发，给 `file-shelf` 加一条分支即可。

## 六、数据模型

目录在 Roaming 的 Levitaire 配置旁，与 `notes.json` 同级：

```
%APPDATA%\levitaire\shelf.json
%APPDATA%\levitaire\shelf\files\<id>.<ext>
```

`shelf.json`：

```json
{
  "version": 1,
  "collapsed": false,
  "items": [
    {
      "id": "shelf-1730000000000-1",
      "kind": "reference",
      "name": "报告.pdf",
      "path": "D:\\docs\\报告.pdf",
      "isDir": false,
      "size": 204800,
      "addedAt": "2026-10-30T01:20:00+00:00"
    },
    {
      "id": "shelf-1730000000001-2",
      "kind": "owned",
      "name": "截图.png",
      "path": "C:\\Users\\<user>\\AppData\\Roaming\\levitaire\\shelf\\files\\shelf-1730000000001-2.png",
      "isDir": false,
      "size": 183240,
      "addedAt": "2026-10-30T01:21:00+00:00"
    }
  ]
}
```

字段约定：

- `kind`：`reference` 或 `owned`。没有第三种。
- `path`：引用存规范化后的源路径；owned 存暂存目录内的绝对路径。展示名用 `name`，不从路径临时解析，避免失效后连名字都没了。
- `sourcePath`：仅「从某条路径复制出来的 owned」填写，值为复制前的源路径。截图、剪贴板位图没有源路径，字段省略。去重看引用的 `path`，以及 owned 的 `sourcePath`。owned 的 `path` 在暂存目录里，和用户刚拖进来的路径对不上，不能拿它去重。
- `size`：加入时的字节数。文件夹为 `null`。列表上的大小不实时监视磁盘。
- 读盘时路径已不存在：条目仍返回，多一个 `missing: true`。不自动删条目（S9 的同一考虑：消失应该看得见）。
- `version` 不是 1：拒绝加载，把原文件改名为 `shelf.json.bak-<时间>`，从空清单启动，并在窗口里说明「清单已备份」。不要静默丢掉用户的引用。

给前端的 DTO 可以带 `missing`，不带「请删除这个路径」之类的能力。`path` 可以给前端用来显示和「打开位置」，但删除与拖出接口忽略前端回传的 path，只认 `id`。

## 七、架构

```
文件暂存架浮窗 FileShelf.tsx
  Ctrl+V / 拖动条目 ──invoke(id 或剪贴板路径)──┐
  tauri://drag-drop 只刷新清单                  │
                                                ▼
HWND 上的 IDropTarget::Drop（返回前）           commands/shelf.rs
  易失文件在这里复制                            薄壳
        │                                       │
        └──────────────► shelf/ ◄───────────────┘
                         mod.rs      状态机、Mutex、原子写
                         add.rs      引用 / 易失复制 / PNG
                         drag_out.rs DoDragDrop，仅 COPY
                         delete.rs   owned 删除 + 重解析点闸
```

前端窗口创建沿用 `src/utils/toolWindows.ts` 的 `ensureXWindow` + `openToolWindow`。Rust 侧不负责把这个 WebView 造出来（便利贴是例外，因为它一张纸条一个窗口）。暂存架只有一个窗口，和通用工具、待办一样由前端 `WebviewWindow` 创建。

### 7.2 命令

| 命令 | 作用 |
|---|---|
| `get_file_shelf_enabled` / `set_file_shelf_enabled` | 与 `BACKEND_TOOLS` 的命名守卫一致：`get_file_shelf_enabled` |
| `show_file_shelf` / `hide_file_shelf` | 显隐。hide 不改清单 |
| `shelf_list` | 返回 DTO 数组。读时刷新 `missing` |
| `shelf_add_paths` | 剪贴板 `CF_HDROP`，以及 Drop 处理里已经落定的路径。逐条处理，返回每条的结果（加入 / 置顶 / 拒绝原因），不要一条失败就丢掉整批。拖入的易失复制不经过前端再调这个命令，避免复制两次 |
| `shelf_add_png` | 参数是 PNG 字节。截图与钉图、以及剪贴板位图共用 |
| `shelf_begin_drag` | 参数是 `id[]`。在窗口所属 UI 线程上进入 `DoDragDrop`，直到松开或取消才返回 |
| `shelf_remove` | 参数是 `id[]`。按 S2 / S3 处理 |
| `shelf_reorder` | 参数是按新顺序排列的 `id[]`。必须正好是现有条目的一个排列；数量、重复或未知 id 对不上时整次拒绝，前端刷新清单、回到磁盘上的顺序 |
| `shelf_clear` | 清空。前端已确认过才调用 |
| `shelf_set_collapsed` | 写入 `collapsed` |
| `shelf_reveal` | 参数是一个 `id`。失效则返回错误，前端把该行标成 missing |
| `shelf_open` | 参数是一个 `id`。用系统默认程序打开文件，文件夹交给资源管理器；失效则返回错误 |

`shelf_begin_drag` 必须是同步命令，跑在主线程（STA）上。标成 `async` 或放进 `spawn_blocking` 之后，`DoDragDrop` 不在窗口那条线程上，拖放不会起来。它会把主线程的消息循环占住，直到放下或取消。这是预期行为。期间：

- S7 拒绝第二次拖出。
- 清单 Mutex 在进入 `DoDragDrop` 之前释放。拖放循环会派发新的窗口消息；锁一直拿着的话，此时进来的 `shelf_list` / `shelf_add_paths` 会和自己死锁。
- `dragging == true` 时忽略落在自己窗口上的加入。否则松手在暂存架上会再收入一份。

实现时先在主线程跑通探针：拖一个引用进同一卷的另一个文件夹，原路径上的文件还在，目标里是副本；再按住 Shift 拖一次，原文件仍在。Shift 那次目标里可以没有新文件。探针没过，不写列表 UI。

## 八、加入规则

对一批路径按下面的顺序处理。第 2 步是整批判断，命中则这一批都不加入；其余步骤逐条执行，命中就停在这一条。

1. 空路径、不存在、规范化失败、无法读取：这一条拒绝，原因「找不到文件」或「没有读取权限」。
2. 正在进行自己发起的拖出（`dragging == true`）：整批忽略。这是批次级判断，不要写成「第一条忽略、后面的照常加入」。
3. 规范化后落在 `shelf/files` 内：拒绝。不允许把暂存架自己的副本再拖进去套一层。
4. 是目录，且在易失路径上：拒绝，原因「临时文件夹不能暂存，请改拖里面的文件」（S6）。
5. 是目录：记为 `reference`，`isDir = true`。不枚举子项，不复制。
6. 规范化路径已经是某条引用的 `path`，或某条仍存在的 owned 的 `sourcePath`：该条移到顶部，不重新复制。owned 副本已经缺失时，不要用旧的 `sourcePath` 挡住新文件——临时文件名会被系统复用。
7. 在易失路径上的文件：复制进 `shelf/files`，记为 `owned`，`sourcePath` 记下源路径（S5）。源文件不动。单次易失复制上限 128 MiB。超过则拒绝，不改记成引用。Drop 返回前要在这条线程里把字节写完，512 MiB 会把放下卡到源程序取消这次拖放。
8. 其余可读文件：记为 `reference`。不受 128 MiB 限制。

易失路径按 S5 的四条判断。比较之前，`GetTempPath` 和候选路径都去掉 `\\?\` 前缀并按不区分大小写比较。只对规范化结果做 `starts_with(GetTempPath())` 会因为前缀不一致而把临时文件当成稳定引用，松手后条目失效。不能写死 `C:\Users\...\Temp`。

拖入的复制必须发生在 `IDropTarget::Drop` 返回给系统之前。Tauri 的 `on_drag_drop_event` 是窗口过程把事件派进队列之后才到的，此时 Chrome 一类来源已经把临时文件删了。这扇窗创建时 `dragDropEnabled: false`，wry 不会先登记目标，所以直接 `RegisterDragDrop` 我们自己的 `IDropTarget`。`RevokeDragDrop` 不把旧目标交回来，包一层做不到；若句柄上已经有目标，先撤销再换上我们的。这扇窗只服务暂存架。前端事件只刷新清单，不再把这些路径交给 `shelf_add_paths`，否则同一次放下会加入两次。

剪贴板粘贴没有这个时序问题，`shelf_add_paths` 在命令返回前完成复制即可。

复制时：

- 目标文件名是条目 id 加原扩展名，扩展名只保留最后一个、且仅 `[A-Za-z0-9]`、最长 8 字符，否则用 `.bin`。不把用户的原文件名拼进暂存目录，避免奇怪字符和超长路径。
- 单文件上限：稳定路径只记引用，不复制。易失复制单次 128 MiB。暂存目录里已有文件加上本次复制超过 2 GiB 时拒绝。引用不占这 2 GiB。
- 复制用「写到同目录临时文件，完成后替换」。失败则删掉临时文件，不留半截 owned 条目。
- 复制前如果源路径的任一祖先是重解析点，仍允许读内容（用户就是想留下这份字节），但目标必须创建在已经通过 S3 检查的 `shelf/files` 里。

`shelf_add_png`：字节为空或超过 128 MiB 则拒绝。截图和剪贴板位图走这条，不走易失路径判断。写入后的条目 `name` 为 `截图.png`，重名时加序号，仅影响显示名。没有 `sourcePath`。

条目数在「即将新增」时检查。置顶已有条目不占用新名额。

## 九、拖出

`drag_out.rs` 用仓库里已有的 `windows` 系绑定，不新增拖放插件。

会话步骤：

1. 用 id 在 Mutex 保护的清单里取出仍存在的路径。有缺失的 id 则整次失败并说明哪一条没有了，避免用户以为三件都拖出去了、实际上只有两件。
2. 置 `dragging = true`。
3. 释放清单 Mutex，再构造数据对象。`CF_HDROP` 使用宽字符（`fWide = TRUE`）。路径去掉 `\\?\` 前缀再放进去：清单内部可以留着规范化形式，资源管理器不接受带这个前缀的拖放路径，中文文件名会失败。同时写入 `CFSTR_PREFERREDDROPEFFECT = DROPEFFECT_COPY`。
4. `IDropSource::QueryContinueDrag` 在 Esc 或鼠标右键时取消。`GiveFeedback` 用默认光标。`DoDragDrop` 的 `dwOKEffects` 只传 `DROPEFFECT_COPY`（S1）。
5. 返回后清 `dragging`。无论目标程序接受与否，清单和磁盘都不改。接受只说明对方复制走了；暂存架不是「拖走即消耗」的篮子。用户要拿走条目，用移除。

拖出过程中窗口可以显得无响应，这是系统拖放循环占着 UI 线程。不要在这个循环里再 `invoke` 回前端刷新清单。

已知的尖锐点，探针里必须碰到：

- WebView 还按着鼠标左键时调用 `DoDragDrop`，捕获可能仍在 WebView2 上。若探针里拖不起来，在调用前用 `ReleaseCapture` 放开，再进入拖放。这一步写进 `drag_out.rs` 的注释，避免后来的人当成可选优化删掉。
- 拖到同一卷的资源管理器时，不按修饰键和按住 Shift 各一次。两次之后源文件都还在原路径。不按修饰键时目标文件夹里应有副本。按住 Shift 时目标可以没有新文件：只允许复制的前提下，系统拒绝移动是正确结果。不要为了让 Shift 也落下一份而把 `MOVE` 加进允许效果。

## 十、删除

`delete.rs` 只接受 owned 条目的 id。

1. 从清单取出 path。`kind` 不是 owned 就只从清单删除并返回。
2. 打开 `shelf/files` 时若目录本身是重解析点，中止，清单也不改（宁可留着一条条目，也不顺着链接删出去）。
3. 规范化 path。比较前两者都变成 `\\?\` 长路径形式。结果必须是 `shelf/files` 的严格子路径，且父目录就是 `shelf/files`（不允许子目录，第一版也不创建子目录）。
4. 从根走到该文件，任一层带重解析属性则中止。
5. `DeleteFileW` 删这一个文件。文件已经不在：视为成功，继续从清单移除。
6. 清单原子写失败：已删的文件找不回来，窗口提示「副本已删除，但清单没写上，重启后会显示为找不到」。不要为了回滚去复写用户目录里的别的文件。

清空是按条目循环调用同一函数，不是 `remove_dir_all`。`remove_dir_all` 在根被调包时没有逐文件闸门。

## 十一、捕获会话

时钟和待办的实际时序不是「整个会话一直藏着」：`start_screenshot_inner` 在抓全屏缓存前隐藏它们，抓完又在遮罩显示前 show 回来，靠全屏遮罩盖住。暂存架不要抄这段恢复。它自己也是置顶窗，若在遮罩 `show` 之后才显示，会压在选区上。

暂存架的规则是：抓纯净画面之前隐藏，会话真正结束才恢复。

| 时机 | 位置 | 对暂存架 |
|---|---|---|
| 截图开始，抓缓存之前 | `start_screenshot_inner` 里隐藏时钟的那一段 | 记录可见性并隐藏 |
| 截图缓存抓完 | 同函数里把时钟 show 回来的那一段（约在 `wait_for_screenshot_overlay_ready` 之后） | **不要** show |
| 截图会话清理 | `cleanup_screenshot_session_inner` | 标志为真且 `tool_still_enabled(..., "file-shelf")` 时 show |
| 录屏选区开始 | 同文件里隐藏时钟的那一段 | 若本次新开了捕获会话，记录可见性；然后隐藏 |
| 录屏选区取消 | `cancel_recording_select_inner` | 与截图清理相同的恢复条件 |
| 长截图抓首帧 | `long_capture.rs` 里再次隐藏时钟的那一段 | 隐藏。可见性沿用截图开始时记下的标志，不要按「当前不可见」再写一次，否则会把会话前开着的暂存架记成关掉 |
| 长截图结束 | `stop_long_capture` 里恢复时钟的那一段 | 按标志恢复 |

`tool_still_enabled` 必须有 `file-shelf` 分支，读 `file_shelf_enabled`。缺这个分支时未知名字按恢复处理，用户在会话中途关掉工具，结束时浮窗会自己弹回来。

## 十三、测试

### 后端

- 引用加入不创建 `shelf/files` 下的文件，清单 path 是规范化路径。
- 临时目录下的文件加入后，源文件仍在，owned 副本内容一致，`sourcePath` 是源路径；把源删掉后条目 `missing == false`（副本还在）。同一源路径再加入一次，只置顶，不产生第二份副本。
- 易失路径上的文件夹被拒绝，清单和暂存目录都没有它。
- 临时目录复制失败时清单没有这条，且没有半截文件。
- 超过 128 MiB 的易失文件被拒绝，不退回成引用。暂存目录总量超过 2 GiB 时同样拒绝。
- `\\?\` 前缀和大小写不同的临时目录路径仍判定为易失，并被复制。
- 文件夹加入后 `isDir == true`，暂存目录没有该文件夹的副本。
- 重复路径只置顶。
- 第 31 条被拒绝，前 30 条顺序不变。
- `shelf_reorder` 按给定顺序落盘，重开清单仍是该顺序；缺项、重复或数量不符时整次拒绝，原顺序不变。
- 移除引用不改变源文件的存在性。
- owned 删除后，暂存目录里该文件没了，目录外的同名文件还在。
- `shelf/files` 换成指向其它目录的 junction 时，删除返回错误，目标目录里的哨兵文件还在。这是 S3 的蜜罐。
- 拖出数据对象里 `Preferred DropEffect` 的 DWORD 只有 `DROPEFFECT_COPY`，且 `DoDragDrop` 的允许效果只有这一项。不要去断言 `IDropSource` 的返回值，那个接口不携带效果。真正的资源管理器落点放在手工探针，不进 CI。
- `shelf.json` 版本不符时原文件被旁路，内存中的清单为空。
- `file_shelf_enabled` 在缺字段的旧配置里是 `false`。

### 前端

- `registry.test.ts` 现有的「BACKEND_TOOLS 覆盖全部工具」「命令名与 id 对应」会自动罩住新 id。不要手写第二份命令名。

- 双击打开调用 `shelf_open`；失效条目不调用。`Shift` 连选按显示顺序选中区间，点面板空白处清空选择。
- 拖入回调收到 `drop` 时只刷新清单，不把 `paths` 再交给 `shelf_add_paths`。粘贴才调用 `shelf_add_paths`。

### 手工探针（实现阶段的门）

1. 把桌面上的一个小文件拖进暂存架，再拖到同一卷的另一个文件夹。不按修饰键时，桌面上的原文件还在，目标文件夹里是副本。按住 Shift 再拖一次时，原文件必须还在；目标里可以没有新文件——只允许复制时，系统拒绝这次移动是正确结果，不要为了让 Shift 也复制成功而把 `MOVE` 加进允许效果。
2. 从 Chrome 或 Edge 把一张网页图片拖进暂存架，立刻再拖到资源管理器。文件能落地。这一步验证的是「复制发生在 Drop 返回之前」，不是验证临时目录字符串。
3. 截一张图，放入暂存架，拖进资源管理器。钉图右键菜单走同一条命令。聊天窗口若显示禁止光标，记成目标程序不接受 OLE 拖放，不要为此把效果改成移动。
4. 开始区域截图时暂存架消失，选区过程中它不压在遮罩上，取消后回到原位。在暂存架上按下并拖动，不会触发文字工具栏的模拟复制。

第 1 步没过，不继续做面板和截图按钮。

## 十四、实施顺序

1. **拖出探针。** 一个最小窗口加一个写死的文件路径，证明 S1。不过就停，换拖放实现，而不是先把 UI 做完再发现拖出去是移动。
2. **`shelf/` 模块与命令。** 加入、清单、删除、上限、蜜罐测试。此阶段可以没有浮窗，用测试当调用方。
3. **浮窗、拖入与拖出一起做。** 路由、窗口创建、自己的 `IDropTarget`（`dragDropEnabled` 保持 false）、列表、移除、清空、收起、拖出、多选、位置记忆、启停、`OWN_WINDOW_LABELS`、`default_window_position` 和鼠标钩子排除。不要先提交一个只能放进、不能拖出的窗口，也不要先用前端 drop 事件充数。
4. **会话隐藏、自启动、截图工具栏、长截图预览、钉图原生菜单。**
5. **补注册表文案、图标、色值，跑前端守卫测试。** 工具 id 在第 3 步就要进注册表，否则面板打不开；这一步只补文案和色值。

不要在第 1 步之前改工具面板，否则用户能打开一个还拖不出去的空窗。

## 十五、风险

| 风险 | 表现 | 对策 |
|---|---|---|
| `DoDragDrop` 与 WebView2 的鼠标捕获打架 | 按下条目没有拖放光标 | 探针里验证 `ReleaseCapture`，写进 `drag_out.rs` |
| `dwOKEffects` 或首选效果里带了 `MOVE` | 同卷或 Shift 拖放把原文件搬走 | S1。探针含 Shift |
| 复制写在 Tauri 的 `on_drag_drop_event` 或前端回调里 | 浏览器临时文件在回调运行前已被删 | 自己的 `IDropTarget`，在 `Drop` 返回前复制。窗口没有先登记的目标可转交 |
| `GetTempPath` 与规范化路径前缀不一致 | 临时文件被当成引用，松手后失效 | 比较前去掉 `\\?\`，并不区分大小写 |
| 拖放循环持有清单锁 | 循环里再进来的命令死锁 | 进入 `DoDragDrop` 前释放 Mutex |
| 主线程被拖放循环占住 | 拖出期间其它浮窗不刷新 | 接受。S7 禁止嵌套。不在循环里调用前端 |
| 聊天软件不吃 OLE 的 `CF_HDROP` | 拖到输入框是禁止光标 | 探针记下来。不改成移动来迁就 |
| 微信等客户端的私有临时目录不在 S5 的四条里 | 松手后条目失效 | 探针碰到再加前缀。不要为了这个把所有文件都复制一遍 |
| 清单与副本删除的顺序 | 文件已删、清单写失败 | 第十节的提示文案；下次 `shelf_list` 标 missing，用户可再移除 |
